> `design/` 与 ADR 的分工：**ADR 裁定「选什么 / 为何不选另一个 / 何时推翻」，
> `design/` 只补实现级细节**（搬运单元、等价性证明、文件级目录、逐批复验断言），
> 不重复也不推翻 ADR。两类的取舍冲突以 ADR 为准；`design/` 发现 ADR 行号或计数
> 错误时，直接改 ADR（未提交批次）或追加落地注记（已提交批次）。
>
> `design/` 内部再分两类：**细化设计页**（如 `frontend-console-plan.md`）答「怎么实现」；
> **开发计划页**（文件名以 `dev-plan-` 开头）答「按什么顺序做、每批何时可开工 / 何时算收口、
> 提交怎么拆」，不转述前两者正文，只引用判据编号与决策编号。三类冲突时优先级：
> ADR > 细化设计页 > 开发计划页（计划页发现上游错误时只登记为门禁，不自行拍板）。
