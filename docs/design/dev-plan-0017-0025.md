## 本页纪律（与 `frontend-console-plan.md` 同源，另加两条）

1. **不转述**：ADR 答「选什么 / 为何不选另一个 / 何时推翻」，设计页答「怎么实现」，
   本页只答「按什么顺序做、每批何时可开工 / 何时算收口、提交怎么拆」。判据一律以
   **编号引用**（如「0022 判据 9」），不复制正文；
2. **计数三要素 + 逐条验证归属**：凡跨批引用的计数写成「公式 + 撰写时实测值 +
   重测时点」，且实测值必须按公式定义**逐条验证归属**（设计页 §1.3 歧义 4 的四条纪律，
   该处曾因「占位符个数 ≠ 可锚定个数」把 97 误算为 99）；
3. **不含工期估算**：AGENTS.md N1 禁止未经实测的数字，而工期无任何测量口径。本页只给
   **工作项数**（可从 ADR 决策条目机械计数，属实测）与相对规模标注（S/M/L，**明示为
   非实测的主观量级，不得当作承诺**）；
4. **不拍板未裁定项**：§6 登记的 5 个门禁，任一在裁定前**不得开工对应批次**；
5. **停批条件优先于进度**：每批的「停批条件」一旦命中即停止该批并回改 ADR，
   不得「先开工后补」（AGENTS.md §10 优先级 1 诚实 > 优先级 6 性能）。

> **ADR 状态行的两种形态（本页实测发现的测量陷阱）**：25 篇中 **23 篇**写
> `- 状态：accepted（…）`，但 `0002` 与 `0005` 写 `- 状态：**accepted（…）**`（带 Markdown
> 粗体）。故 `grep -l "^- 状态：accepted"` 只命中 23，**会误报「有 2 篇未 accepted」**。
> 正确命令为 `grep -q "^- 状态：\*\{0,2\}accepted"`；权威证据以
> `grep -h "^- 状态：" infra/adr/0*.md \| sed 's/^- 状态：\*\{0,2\}\([a-z]*\).*/\1/' \| sort \| uniq -c`
> 的输出为准（2026-09-14 实测 = `25 accepted`）。
> 教训：**计数公式必须先验证它自己的召回率**，否则会把「模式太窄」误读为「事实不符」
> （同型：KL #31 第五项 (b) 的检索过滤与分类判据同源）。另：`grep -lc` 因 `-l` 与 `-c`
> 语义冲突会返回无意义值（实测 50），**不得用作计数依据**。

「预计减少 X% 错误」。0025 背景 3 的 10 组合实验是**合成行**实验，只证轴选择逻辑，
**不构成任何 EX / 数据正确性声明**——本页任何地方都不得把它当作准确率引用。

## 7. 本页能证伪什么

1. **§1.2 的每条边都给了具体后果**，若某条边的后果被实测证伪（例如 P0a 在 P0b 之后
   执行也能判定第三方包许可证兼容性），则该边可松绑——**但须回写 0018 落地注记 3**，
   不得在本页直接改序；
2. **§0 的起点实测表是可复测的**：每批开工前重跑该表的复测命令，若某批的证据已消失
   （例如 `/health` 已返回 8 键），说明该批已被落地而本页未更新——**改本页并标注重测日期**，
   不得让本页变成第二套过期计数源（这正是 README KL #31 第五项登记的债务形态）；
3. **§5 的计数表是全链最强的漂移探针**：任一格的重测值 ≠ 预期值，
   要么对应 ADR 的证伪条件被触发（回改 ADR），要么本页的预期值算错（回改本页并留纠错记录）。
   两种情况都**不允许**通过调整断言让测试变绿；
4. **本页自身的最可能失效形态**：新增 ADR-0026+ 并插入批次链。此时 §1.1 的顺序图、
   §4 的提交矩阵、§5 的计数表三处需同批更新；只更新其一即产生本页试图消除的那类不一致。
