## 背景

### 1. 现状：飞轮已"半落地"且诚实空转，但 §3.3.3 的新增部分无裁定、且踩红线

"数据飞轮"这个词在仓库里有两种含义，必须先拆开，否则会把已落地的当作待办、
把危险的当作已授权：

| 组成部分 | text2insight §3.3.3 措辞 | 代码现状（2026-09-17 核实） | 是否有 ADR |
|---|---|---|---|
| 反馈采集 | 用户对澄清的选择、对 SQL 的修改、对结果的赞踩 | `agent/feedback.py` 落地**一键纠错**（5 种 kind），但"澄清选择/SQL 修改"**未结构化采集** | 无（散见于 Day 46） |
| 模型迭代 | 定期用标注数据微调 | `lora/flywheel.py` 五阶段**落地但空转**（0 失败样本 + 无 GPU） | ADR-0008（训练目标）；飞轮机制本身无独立 ADR |
| **自动沉淀·同义词** | 新同义词**自动写入向量库** | ❌ 无实现 | 无 |
| **自动沉淀·指标** | 指标修改**自动更新语义层版本** | ❌ 无实现 | 无 |
| **自动沉淀·缓存** | 高频查询**自动优化缓存** | ❌ 无实现、无缓存层 | 无 |

前两项是"把已有机制纳入统一视图"；**后三项是本 ADR 真正要裁定的新增能力，且它们的字面描述
直接违反项目红线**（见背景 2）。text2insight §3.3.3 的"自动"二字是本文存在的核心理由——
它许诺了一个与"Git 唯一事实源 + 人工确认门槛"不相容的系统。

### 2. 三处硬冲突（"自动沉淀"若照字面实现即撕毁既有契约）

**(a) "新同义词自动写入向量库" → 向量库变成第二事实源。** ADR-0015 明确同义词的权威源是
`semantic/synonyms/*.yml`（Git），`retrieval/` 的向量索引是**派生物**。一旦飞轮把同义词
直接写进向量库，检索就能命中一条"没进 Git、`make lint` 查不到、评审看不见"的措辞——
这正是 ADR-0015「双权威源禁令」和 ADR-0002「Git 唯一事实源」要消灭的形态。且 ADR-0016 已给
出同构问题的正确解法：**机器生成值本体、人工追加别名**——沉淀走的是"提议 + 人工 + Git"，
不是"自动写运行时存储"。

**(b) "指标修改自动更新语义层版本" → 自动写 Git + 可能造同名 active 指标。** 语义层变更是
Git 一等对象（ADR-0002），须 `make lint`（结构 + 唯一性 + 权威源唯一）+ eval 回归门禁。
"自动更新"要么绕过这些门禁（不可接受），要么自动提交 Git（等于给系统改架构定义的写权限，
违反 N8 的"同一业务词只有一个权威定义"需人工裁决）。

**(c) "高频查询自动优化缓存" → 当前架构无缓存层，属过度设计。** §10 优先级 5：不过度设计。
确定性 Compiler 已快（纯本地 AST 计算）、LLM 路径仅候选可达（`allow_candidate`，默认关）。
没有 profile 证据证明缓存是瓶颈之前，引入缓存键空间与失效逻辑是拿复杂度换不存在的问题。

### 3. 诚实性：空转是设计结论，不是可被"美化"的缺陷

README `:198` 与 `docs/release-notes-v0.1.md:87` 已如实登记：SFT 飞轮"**空转实测**"
（0 失败样本 → scan {} → export 0 → build exit 0 → train exit 2，state 绑定 sha 落盘），
`eval/failures/README.md:26` 记"当前空集"。**本 ADR 不得把飞轮写成"已驱动准确率提升"**（N1）——
它提升多少只能来自未来 `eval/reports/<sha>.json` 的实测。ADR 只裁定**机制与边界**，不产出效果数字。

### 4. 约束（引既有红线，不重复论述）

AGENTS.md §0.2「确定性优先」、§0.3「诚实是不可协商红线」、N1/N2/N4/N8、
§10 优先级 1（诚实）> 2（安全）> 3（可复现）> 5（不过度设计）；
ADR-0002（Git 唯一事实源）、ADR-0008（SFT 人工确认门槛）、ADR-0010（评测门槛 + 数字溯源）、
ADR-0015（同义词权威源在 Git，retrieval 是派生索引）、ADR-0016（值域"机器生成 + 人工追加"范式）。

## 备选方案

争议点：**反馈 → 知识沉淀**这条链上，哪些环节可自动化、哪些必须人工闸口。

| 方案 | 优势 | 劣势 |
|---|---|---|
| **① 分级闸口（选定）**：采集全自动 → 候选生成可自动 → **落权威事实源（Git 语义层/同义词/值域/SFT）必人工 + CI 门禁** | 与 ADR-0002/0008/0015/0016 完全一致（复用"机器生成 + 人工追加"既有范式）；向量库永远派生、不升格为源；自动化收益（省采集/归纳）与安全性（守住权威源）各取所需 | 沉淀有人的延迟，非"实时自进化"；需为三类候选（同义词/值域别名/指标 proposal）定义统一格式与人工入口 |
| ② 全自动沉淀（照 text2insight §3.3.3 字面） | 真正"自进化"、零人工 | **同时违反 ADR-0002/0015（第二事实源）、N8（同名指标无人裁决）、ADR-0010（未经评测门禁的语义变更直接生效）**——否决 |
| ③ 不做飞轮，只保留现有人工流程 | 零风险、零新增代码 | 放弃 §3.3 唯一已部分落地的能力线；反馈信号持续流失；text2insight 阶段三彻底空心化 |
| ④ 只做 SFT 飞轮，语义沉淀永久排除 | 与现状一致（现状就只落了 SFT 侧） | 但 §3.3.3 的"同义词/值域"沉淀是真实高价值需求（未登录措辞命中），一刀永久排除过于保守——改为"人工闸口下可做"（决策 ②③）更合理 |

**选定 ①**：自动化的是"采集 + 归纳候选"，人工闸口守的是"写入权威事实源"。这是对
"哪些能自动、哪些不能"的正面切分，而非在②/③两极摇摆。

---

## 决策

### ① 三段式分级：采集自动 / 候选自动 / 落源人工

把飞轮链路切成三段，逐段定自动化权限：

```
[自动] 反馈采集        →  eval/failures/**（status=pending_review），现有一键纠错 + 新增澄清选择/SQL修改采集
[自动] 候选生成        →  从 pending 反馈离线归纳「候选」：新同义词提议 / 值域别名提议 / 指标变更 proposal
[人工] 落权威事实源     →  人工把候选 approve 进 Git（semantic/synonyms/*.yml、semantic/values/*.json 追加、
                          semantic/metrics 定义），make lint + eval 回归过门禁后才生效；SFT 语料沿用 Day 41 五阶段
```

**铁律（全链路不变量）**：任何一环都**不得**让"运行时存储（向量库 / 内存缓存 / 在线词典）"
成为某事实的**唯一**权威——运行时存储只可由 Git 重建。`retrieval/` 的向量索引在
同义词 Git 变更后**整体重建**（派生），飞轮永远不直接写向量库。

### ② 同义词/值域别名沉淀 = 提议 + 人工 + Git，向量库降为派生索引

- 反馈里出现"用户用了某措辞 → 系统未命中 → 经澄清确认对应指标/维度/值" →
  飞轮**离线**生成**候选**（记 source 反馈文件路径、措辞原文、建议归属对象），落
  `semantic/synonyms/_candidates/`（新目录，`_*` 前缀 = 非权威候选区，
  `make lint` 明确不把它当权威源校验，沿用 ADR-0015 对 `semantic/` 下 `_*` 归档区的处理纪律）；
- 人工审核 → 把通过的措辞追加进 `semantic/synonyms/<locale>.yml`（同义词）或
  `semantic/values/<model>.<field>.json` 的**别名列表**（值域，ADR-0016 的"人工追加别名"入口，
  **不改机器生成的值本体**）；
- Git 变更后重跑 embedding 重建 `retrieval/` 索引（既有 dense/bm25 流程，非新机制）。
- **不做**：自动改 Git、自动写向量库。理由见背景 2(a)。

### ③ 指标/语义层变更 = 只产 proposal，绝不自动改定义

- 反馈中"指标选错/口径不对"（`wrong_metric` / `wrong_value`）→ 飞轮生成
  **语义层变更 proposal**（结构化：受影响 metric、变更类型、证据反馈列表、疑似正确定义），
  落 `semantic/migrations/` 旁的 proposal 载体或 `eval/failures/_proposals/`（非权威区）；
- **生效唯一路径** = 人工依 proposal 改 `semantic/ossie/*.yaml` →
  `make lint`（结构 + **权威源唯一性**，含 N8 同名 active 检查）→ `make eval` 回归 →
  按 ADR-0010 报告门禁合入。飞轮**不提交、不改写**任何语义层文件；
- 与 ADR-0014 ① 一致：飞轮不自动新增/改指标定义，那是需评审的一等对象变更。

### ④ SFT 语料沉淀 = 沿用 Day 41 五阶段人工闸口，纳入统一飞轮视图但不改其红线

`lora/flywheel.py`（scan 自动归类 → **review 人工闸口** → export 双闸：approved +
`validate_plan_json` → build 防泄漏过滤 → train blocked 如实记录）**保持不变**。本 ADR：
- 明确"用户反馈"（`agent/feedback.py`，origin=user）与"评测失败"（failure_collect）是
  **两个采集入口、一个飞轮链路**（决策 ①），二者都先落 pending_review，人工确认后才可
  进 approved → SFT（AGENTS.md / ADR-0008 / `eval/failures/README.md` 同一门槛）；
- 修复一处现状不一致：`export_approved` 用 `payload["sample"]["question"]` 读取，而
  `agent/feedback.py` 写的是**顶层** `question`（无 `sample` 包裹）——两类记录 schema 未对齐，
  落地时须统一为同一 pending 形态，否则 user_feedback 即便人工 approve 也会被 export 静默跳过
  （见代价 ①）。

### ⑤ MVP 明确不纳入（区分"设计性不做"与"待办"，不写成已完成）

- **高频查询自动优化缓存**：当前无缓存层、无 profile 证据（背景 2(c)）→ **设计性不纳入**，
  触发条件见"什么情况下应该推翻"；
- **任务完成度评估体系**（text2insight §3.3.4）：与 ADR-0010 的 EX/Plan Acc 二元口径**直接冲突**
  （"废弃单一 SQL 准确率"需先仲裁既有评测契约）→ **另立 ADR**，不并入本飞轮决策；
- **LLM 自动改写提示词/口径**：提示词变更须走 `agent/prompts/*.yaml` 版本管理 + CI 回归评测
  （PromptOps，AGENTS.md 7.4），飞轮**不自动改提示词**，至多产 proposal（同 ③ 姿态）。

### ⑥ 运营状态如实登记（防 N2）

本 ADR 采纳后，飞轮对外表述固定为：
- SFT 侧机制**已落地**，端到端轮转**未验证**（无失败样本 + 无 GPU，README/release-notes 已记）；
- 同义词/值域/指标三类**语义沉淀路径 = 本 ADR 新裁定，尚未实现**；
- **禁止**任何"准确率因飞轮提升 X%"的声明，除非来自 `eval/reports/<sha>.json`（N1）。

## 理由

1. **选"分级闸口"而非"全自动"，是把 ADR-0016 已验证的范式复用到底**。值域已确立"机器生成
   值本体、人工追加别名"——同一套"自动归纳候选、人工落权威源"的逻辑天然适用于同义词与指标。
   引入"自动写 Git/向量库"不是新能力，是对既有单一事实源承诺的违约。
2. **向量库降为派生索引是整条链最关键的一处约束**。一旦允许写运行时存储，`make lint` 与 code
   review 就查不到"系统实际用什么措辞匹配"，诚实性从"文档不造假"退化为"运行时行为不可审计"。
   保持"Git → 重建索引"单向，等于把飞轮的全部效果纳入既有门禁。
3. **把"任务完成度评估"切出去，是因为它会动摇评测地基**。§3.3.4 想"废弃单一 EX"，而 EX/Plan Acc
   + 快照绑定正是项目可信数字的根（ADR-0010）。这类口径变更必须独立评审、独立证伪，
   不能搭飞轮的便车偷偷改口径（N1 的隐性形态）。
4. **飞轮只产 proposal 不改 Git，是把"系统能进化"和"进化受控"分开**。真正的自进化叙事很诱人，
   但金融问数的口径变更是治理事件（谁定义"不良率"必须可追责），自动化到"改定义"就越过了
   确定性优先与人工治理两道线。

## 代价与限制

① **存在必须先修的现状缺陷：两类反馈记录 schema 不一致**
`agent/feedback.py` 写顶层 `question/kind`（无 `sample` 包裹），`lora/flywheel.py::export_approved`
按 `payload["sample"]["question"]` + `sample["answer_plan"]` 读取——决策 ④ 要统一 pending 形态，
否则 user_feedback 人工 approve 后仍被 export 跳过（静默丢样本）。这是本 ADR 落地的**前置修复项**，
不是假设风险（代码级可验证）。

② **候选归纳本身可能引入噪声，且归纳质量无客观度量**
从 pending 反馈自动归纳"建议同义词/别名"是启发式，可能提议低质候选。缓解 = 候选只进 `_candidates/`
非权威区 + 人工 approve 才落 Git；但"候选 precision"无黄金标注即不可测（N1）——故**不声称候选质量，
只声称候选不自动生效**。

③ **沉淀有人的延迟，非"实时自进化"**
决策 ①②③ 意味着飞轮的"闭环"含人工环节，吞吐受审核带宽限制。这是**特性不是缺陷**（守权威源），
但须诚实标注：不满足 `text2insight.md` §3.3 隐含的"全自动进化"预期。

④ **SFT 端到端仍未跑通（承接现状）**
决策 ④ 不改 Day 41 空转状态；本 ADR 不承诺何时产生首批 approved 样本，也不承诺训练结果
（N1/N2；GPU 与失败样本齐备后按 ADR-0008 验证方式补）。

⑤ **需新增非权威候选目录并接入 lint 排除**
`_candidates/` / `_proposals/` 属新目录，须同步 `semantic/lint.py` 的权威源唯一性校验**排除**
这些 `_*` 区（避免候选被误当权威定义、或触发 N8 检查），并补 ADR-0015 对 `semantic/` 下
`*.yaml` 归属的既有约束说明。

> **落地注记（2026-09-17，开工实测修正）**：本条的"须同步 lint 排除"**弱于实际**——
> `check_semantic_authority` 已豁免 `_*` 前缀目录（`lint.py:70`），`VALUES_DIR.glob("*.json")`
> 与 `check_value_profiles` 均为**非递归** glob（`lint.py:197`），`load_locale_synonyms` 只读
> 固定文件名（`synonyms/{en_us,zh_cn}.yml`）。故把候选放进 `semantic/**/_candidates/` **无需改
> lint 逻辑**，既有的非递归 + `_*` 豁免已天然隔离。本条据此**收窄为**：新增回归断言**锁死**
> 这三处不变量（防未来把 glob 改成递归、或把候选放进非 `_*` 目录），而非新增排除分支。

## 什么情况下应该推翻

- **出现"候选审核带宽成为瓶颈"的实测证据**（如人工确认队列持续增长、反馈→生效周期可测地过长）
  → 评估在**保留 Git 权威源与 lint/eval 门禁**前提下，把"低风险同义词追加"改为"自动开 PR、人工
  一键批准"（把人工从"写"降级为"批"）；**仍不得**自动 merge（推翻的是操作成本，不是单一事实源）；
- **引入真实查询缓存层且有 profile 证明缓存命中是瓶颈** → 才启动"高频查询自动优化缓存"设计
  （决策 ⑤ 第一条），需独立评测（N1）；
- **"任务完成度评估"独立 ADR 通过并推翻 ADR-0010 二元口径** → 飞轮的评测门槛随之改，但人工闸口不变；
- **retrieval 侧出现"不写向量库就无法满足的实时命中需求"** → 直面背景 2(a) 冲突，须先改 ADR-0002/0015

## 验证方式

> 本文是 proposed；落地前以下均为**待执行**，不产出任何效果数字（N1）。语义沉淀路径按
> ADR-0010「评测先行」：先落失败/候选基线（不入库），再写实现。

1. **单一事实源不破坏（决策 ①②，守 ADR-0002/0015）**：`tests/` 新增断言——飞轮任何产物
   **只落** `_*candidates/`、`_*proposals/` 或 `eval/failures/**`（pending），
   **不落** `semantic/synonyms/*.yml`、`semantic/values/*.json` 值本体、`semantic/ossie/*.yaml`、
   不写 `retrieval/` 索引。以 `grep` + 临时目录写监听断言飞轮运行不改权威源；
2. **schema 统一（前置修复 ①）**：`tests/test_feedback.py` / `tests/test_flywheel.py` 断言
   user 反馈与评测失败经统一 pending 形态后，`export_approved` 能一致读取（不再静默跳过
   user_feedback）；补一条"approved 的 user_feedback 可被导出"的正向用例锁死该缺陷已修；
3. **候选不自动生效（决策 ②③）**：契约测试——给定含未命中措辞的反馈，飞轮生成候选后，
   `make lint` 结果与候选生成前**逐字一致**（候选在 `_*` 非权威区，不进权威校验、不新增 active 指标、
   不触发 N8）；人工把候选 approve 进 Git 后，`make lint` 才反映新同义词；
4. **指标 proposal 只读（决策 ③）**：断言飞轮对 `wrong_metric` 反馈的产物是 proposal 文件，
   `semantic/ossie/*.yaml` 在飞轮运行前后 `git diff` 为空；
5. **派生索引重建（决策 ②，防第二事实源）**：同义词 Git 变更后重跑既有 embedding 流程，
   断言 `retrieval/` 命中来自 Git 内容，而非任何"运行时写入"（不存在向量库直写接口 = 结构不变量）；
6. **运营状态诚实（决策 ⑥）**：README 能力登记表与 Known Limitations 同步——"数据飞轮：
   SFT 侧机制已落地、端到端轮转空转（无失败样本/GPU）；语义沉淀路径为本 ADR 裁定、待实现"，
   **不得**出现"已闭环/已提升准确率"字样（N2/N4），文档措辞以 `grep` 自查无未溯源的效果数字；
7. **全量回归**：`make lint && make test && make eval`；SFT 轮转在具备 approved 样本时按
   ADR-0008 验证方式执行（`lora/data/flywheel-state.json` 绑定 sha 落盘）。

**证伪条件**：若判据 1/3/5 任一显示飞轮改了权威源或向量库被直写，则"分级闸口 + 派生索引"的
基础被证伪，本 ADR 不成立，须回退到"飞轮仅产报告、不产任何可生效产物"的最小形态；若判据 2
证实 user_feedback 与评测失败无法在不破坏既有 pending 契约下统一，则决策 ④ 的统一链路需拆成
两条独立导出通道（增实现成本，不改红线）。
