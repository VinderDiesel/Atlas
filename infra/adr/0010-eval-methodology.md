# ADR-0010：评测方法论（可信数字的唯一来源）

- 日期：2026-09-03
- 状态：accepted（落地：eval/runner.py、eval/gold/ 51 例、data/snapshots/）
- 相关：ADR-0001（为什么用公开数据）、ADR-0006（金融场景切换）、AGENTS.md
  第 9 节（数字与声明规范）、README 第 7/9/10 节

---

## 背景

"可信 AI 问数平台"的信任来自**每个数字都能被复现**。NL2SQL 领域最常见的翻车是
把模型报告（Spider/BIRD 论文分）当产品分、把单次 demo 当评测、把无脚本的估算
写进文档。Atlas 的评测方法论必须回答四个问题：

1. 测什么（口径）？2. 在什么数据上测（快照）？3. 数字怎么出（脚本）？4. 谁负责
   （人工确认门槛）？

## 备选方案

| 方案 | 优势 | 劣势 |
|---|---|---|
| **自建黄金集 + 快照绑定 + 脚本报告（选定）** | 口径可控、可复现、可解释；数字与 commit 一一对应 | 建集成本高；覆盖面有限（51 例） |
| 直接报 Spider/BIRD 分数 | 有公认基线 | 与企业场景口径不同（N10：禁止混报）；测不出语义层/Guard 价值 |
| LLM-as-judge 自动判分 | 省人力 | 判断不可复现（judge 换版本结果漂移），违反诚实红线 |
| 人工抽查 demo 截图 | 快 | 无脚本数字（N1 禁止），不可回归 |

## 决策

1. **主评测 = 自建黄金集（gold/）**：51 例（金融域 50 + TPC-DI 语境回归），
   每条含问句、标注 Plan（metric/dimensions/time/filter）、期望 kind、
   期望出口 SQL 与歧义原因（gold-104/121/122/148 等反问用例锁"不猜答"口径）；
2. **口径二元**：EX（Execution Accuracy，执行结果与固定快照一致）与 Plan Acc
   （逻辑计划与标注一致率），分开报告，不使用含糊的"准确率"（术语表）；
   歧义用例按"反问且 0 SQL 执行"计 clarify 达标，不折算进 EX；
3. **数据快照绑定**：评测只跑 data/snapshots/<sha>.meta.json 锁定的表与行数
   （N6），meta 记录 git sha 与 row_counts；结果归一化（Decimal→str）后
   算 result_hash 落报告，防"数据变了评测还过"；
4. **报告即产物**：make eval 产出 eval/reports/<git-sha>.json（或显式命名），
   报告含逐例明细（kind/轨迹/Guard 出口 SQL/行数/latency/归因）；
   README/文档引用数字必须能溯源到报告文件（Day 54 审计逐项核对）；
5. **对照集只作参照**：Spider/BIRD 若报告，单独成节、注明"公开集对照，
   与企业场景口径不同，不混报"（N10）；
6. **失败样本回流门槛**：评测失败样本 → eval/failures/ → **人工确认后**才可进
   SFT 语料（lora/build_pairs）与导出（eval/export 的 approved 口径）；
7. **端到端验收独立成档**：5+1 场景真实 Doris 验收（docs/e2e-acceptance.md）
   与单元/契约测试分离，作为发布门禁（make e2e，失败退出码 1）。

## 理由

1. 黄金集 + 快照让 EX 成为**可复现常量**而非趋势数字：同一 commit 重跑必须同分；
2. 快照 sha 与 git sha 绑定使"评测结果"可被 code review 检查——数字造假
   在机制上不可行（报告由脚本生成，禁止手改）；
3. 人工确认门槛把"失败样本 → 训练语料"变成有审计的闭环，防止模型学错答案。

## 代价与限制

- 51 例覆盖面有限：未覆盖的指标形态（多 join/窗口函数/复杂 time filter）会
  静默漏测 → 靠 Known Limitations 与每日新增 gold 缓解（门槛：语义层变更必须
  带用例，AGENTS.md 8）；
- 结果归一化（hash 口径）需要维护（如 Decimal 与浮点显示差异）；
- 真实 Doris 验收依赖本机环境（make up + seed + 快照锁定），CI 只跑单元/契约层
  ——e2e 属发布前人工门禁。

## 什么情况下应该推翻

- 黄金集覆盖出现系统性空洞（如新增 5+ 指标而用例 <2 条/指标）→ 先补用例，
  若补不过来则**缩小宣称范围**（README/KL 同步），不得扩大数字口径；
- LLM-as-judge 出现可复现标准（judge 版本锁定 + 与人工一致率实测达标）→ 可
  作为**辅助**通道，主评测仍以黄金集为准；
- 快照绑定导致成本不可承受（seed 时间/存储）→ 允许缩表子集，但必须记录
  缩表声明，不得在缩表前后混报同一数字。

## 验证方式

- make eval 全绿 + eval/reports/ 报告存在且含逐例明细（任何数字声明能溯源）；
- 同一 commit 重复 make eval 结果一致（报告内容逐字节比对）；
- docs/e2e-acceptance.md 6/6 通过记录在档；
- README 第 9 节引用格式自查：数字都带口径与产物路径（Day 54 审计表）。
